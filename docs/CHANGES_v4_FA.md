# تغییرات v4 — ثبت ۵ گوشی و اصلاح کادر نصب

- اصلاح `TextEditingController` برای کد نصب، نام گوشی، PIN ثبت و PIN ورود؛ کنترلرها اکنون در State ایجاد و در dispose آزاد می‌شوند. پس از refresh دوره‌ای مقدار تایپ‌شده حفظ می‌شود.
- پذیرش ارقام فارسی و عربی PIN و تبدیل به ارقام استاندارد هنگام هش/بررسی.
- شناسه توکن مستقل ۲۵۶ بیت برای هر گوشی و ذخیره فقط SHA-256 آن در NVS، حداکثر پنج جایگاه.
- مهاجرت خودکار توکن نسخه قبلی از `sclauth/tokenSha` به `sclauth/t0` بدون پاک کردن NVS.
- افزایش `AP_MAX_CLIENTS` از ۴ به ۵ برای امکان اتصال هم‌زمان پنج گوشی.
- حذف `pairing_window_closed` و شرط `millis()>600000UL`.
- حفظ کد نصب اختصاصی، کنترل تلاش ناموفق و ظرفیت پنج گوشی.
- API محلی اضافه‌شده: `GET /api/v1/phones` و `POST /api/v1/phones/revoke` با توکن مجاز.
- صفحه مدیریت گوشی‌های ثبت‌شده در تنظیمات محلی، با امکان لغو دسترسی یک توکن.
- افزوده شدن راهنمای کامل `docs/PAIRING_5_PHONES_FA.md`.
- اضافه‌شدن تست C++ میزبان `tools/test_pairing_host.py` برای آزمون شبیه‌سازی‌شده، و به‌روز شدن تست ایستا و workflow فریمور.

**محدودیت تست:** رفتار بخش احراز هویت در محیط C++ میزبان شبیه‌سازی و پاس شد. تست Flutter/Arduino روی SDK و برد واقعی هنوز انجام نشده است. تنها راه تأیید ساخت موبایل/فریمور در محیط شما اجرای GitHub Actions و تست روی سخت‌افزار است.
