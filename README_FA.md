# Smart Car Lock — پروژه یکپارچه Android / iOS / ESP32 / Server

**وضعیت: نسخه اولیه توسعه (Unverified / نیازمند Verify و تست سخت‌افزاری).** هیچ فایل APK یا IPA از پیش کامپایل‌شده داخل بسته نیست. سورس برای ساخت از GitHub Actions فراهم شده است.

## ساختار

| مسیر | کاربرد |
|---|---|
| `app/` | برنامه Flutter برای Android و iOS؛ فارسی/انگلیسی/عربی، حالت روشن و تاریک |
| `firmware/smart_car_lock_mobile_api.ino` | فریمور ESP32-S3؛ حذف صفحات HTML و جایگزینی با API محلی |
| `.github/workflows/mobile.yml` | ساخت Android APK و iOS app/IPA در GitHub |
| `.github/workflows/firmware.yml` | کامپایل خودکار فریمور ESP32-S3 |
| `server/` | بک‌اند اولیه FastAPI + SQLite + MQTT برای چند خودرو |
| `docs/PROTOCOL.md` | قرارداد API و پیام‌های MQTT |

## امکانات موجود در این مرحله

- داشبورد به سبک موبایل با آیکون‌های Wi-Fi، GSM، GPS و اینترنت و نمایش وضعیت چهار خروجی.
- باز و قفل‌کردن درها و تحریک صندوق در حالت محلی؛ در حالت ابری با درخواست امضاشده و شروط ایمنی فریمور.
- بخش‌های تنظیمات AP (شامل **weakAuto** و آستانه سیگنال)، GPS/Safe Zone، SIM800 و فرمان‌های SMS، MQTT، RFID و نام‌گذاری خروجی‌ها.
- تنظیمات حساس در حالت ابری نمایش داده نمی‌شوند و فقط از وای‌فای محلی قابل ویرایش‌اند.
- ثبت همزمان حداکثر ۵ گوشی برای هر خودرو، توکن مستقل هر گوشی، PIN شش‌رقمی انتخابی و ورود بیومتریک (در صورت پشتیبانی دستگاه).
- انتخاب خودکار اتصال: اول API محلی، درصورت نبودش HTTPS سرور.
- پنل اولیه API برای کاربران، انقضای حساب و چند خودرو در سرور؛ **پنل مدیریتی گرافیکی هنوز ساخته نشده**.

## ۱. ساخت APK بدون Android Studio با GitHub

1. از فایل ZIP خروجی، پوشه `smart_car_lock_project` را در رایانه استخراج کنید.
2. در GitHub یک مخزن **Private** جدید ایجاد کنید (برای کد سامانه خودرو Private بهتر است).
3. محتویات پوشه را در ریشه مخزن آپلود کنید، به‌طوری‌که `.github/workflows/mobile.yml` در همین مسیر باقی بماند. پوشه `.github` را حذف نکنید.
4. در مخزن وارد **Actions** شوید و `Build Android and iOS` را اجرا کنید (`Run workflow`).
5. پس از اتمام موفق Job اندروید، از قسمت **Artifacts** فایل `smart-car-lock-android-apk-test-signed` را دانلود کنید.
6. APK فعلی برای آزمایش ساخته می‌شود، امضای انتشار دائمی آن باید بعداً با keystore خصوصی تنظیم شود.

Workflow، ساختار Android/iOS را روی Runner با `flutter create` تولید می‌کند؛ روی کامپیوتر شما Flutter یا Android Studio لازم نیست.

## ۲. ساخت iOS / IPA

ساخت iOS روی GitHub با macOS runner امکان‌پذیر است؛ اما **IPA قابل نصب** به Apple Developer، Certificate و Provisioning Profile معتبر برای Bundle Identifier پروژه و در روش Ad Hoc به ثبت شناسه دستگاه‌ها نیاز دارد. ساخت بدون امضا فقط یک `.app` غیرقابل نصب تولید می‌کند.

برای مسیر امضاشده باید این Secrets در GitHub ثبت شوند:

- `IOS_P12_BASE64` — فایل گواهی `.p12` به صورت base64
- `IOS_P12_PASSWORD` — گذرواژه گواهی
- `IOS_PROFILE_BASE64` — پروفایل provisioning به صورت base64
- `IOS_KEYCHAIN_PASSWORD` — پسورد تصادفی برای Keychain موقت Runner
- `IOS_TEAM_ID` — Apple Team ID ده‌کاراکتری

این بخش، الگوی اولیه CI است و تا تنظیم دقیق Bundle ID، Profile و ExportOptions مطابق حساب توسعه‌دهنده ممکن است نیاز به تنظیم بیشتر داشته باشد. گواهی و کلید خصوصی را در مخزن عمومی نگذارید. اگر Secrets تنظیم نشده باشند فقط خروجی **unsigned** تولید می‌شود.

## ۳. آماده‌سازی فریمور ESP32

1. فایل `firmware/smart_car_lock_mobile_api.ino` را در Arduino IDE قرار دهید.
2. بالای فایل، مقدار `SCL_PAIRING_SECRET` را به یک کد اختصاصی تصادفی حداقل ۱۲ کاراکتری تغییر دهید و آن را **به‌صورت عمومی در GitHub قرار ندهید**.
3. رمز پیش‌فرض اکسس‌پوینت `12345678` را نیز پیش از استفاده واقعی عوض کنید. این نسخه برای حفظ سازگاری تنظیمات قبلی دستگاه، نام و رمز AP ذخیره‌شده در NVS را حفظ می‌کند.
4. برد ESP32-S3 و کتابخانه‌های `TinyGPSPlus` و `MFRC522` را نصب و ابتدا Verify کنید.
5. فقط روی میز آزمایش با خروجی‌های جداشده از رله‌های خودرو آپلود کنید.
6. گوشی را به اکسس‌پوینت وصل کنید، نرم‌افزار را باز کنید و هر زمان خواستید (بدون محدودیت ۱۰ دقیقه‌ای) با کد اختصاصی دستگاه Pair کنید؛ حداکثر ۵ گوشی قابل ثبت است.
7. پس از Pair، نرم‌افزار توکن را در Secure Storage نگه می‌دارد؛ PIN/بیومتریک فقط قفل ورود به نرم‌افزار است.
8. اگر توکن از گوشی پاک شود، آن گوشی باید مجدداً با کد نصب ثبت شود. درصورت تکمیل ظرفیت، از گوشی ثبت‌شده دیگر می‌توان دسترسی گوشی قبلی را لغو کرد. جزئیات در `docs/PAIRING_5_PHONES_FA.md`.

**مهم:** ارتباط HTTP محلی تنها در شبکه WPA2 اکسس‌پوینت دستگاه است و رمزنگاری سرتاسری در لایه HTTP ندارد. برای استفاده عمومی امنیت بیشتری (به‌ویژه ضد MITM و Provisioning سخت‌افزاری) نیاز است.

## ۴. رفتار حفظ‌شده سیستم

- SMS، GPS، RFID، عملکرد حلقه Location و منطق فعلی حفاظت سیگنال ضعیف در قسمت‌های اصلی حفظ شده‌اند.
- گزینه قطع و وصل رله در نرم‌افزار فقط در صفحه تنظیمات اکسس‌پوینت قرار دارد.
- کد فعلی هنگام افت Wi-Fi می‌تواند رله‌ها را قطع کند. **این منطق برای خودرو در حرکت خطرناک است.** این رفتار به خواسته شما تغییر داده نشده و باید پیش از نصب واقعی با شرط ایمنی سخت‌افزاری اصلاح شود.
- API موبایل، فرمان مستقیمی برای قطع سوخت و سوئیچ ارائه نمی‌کند.
- OTA قدیمی با رمز مشترک در این نسخه غیرفعال شده است.

## ۵. ارتباط ابری

درحالت آنلاین، برنامه با **HTTPS** به سرور `smartcarlock.ir` متصل می‌شود. دستگاه همچنان با GPRS/SIM800 به MQTT Broker (TLS پورت 8883) ارتباط برقرار می‌کند. برنامه از اینترنت موبایل خود استفاده می‌کند؛ روی گوشی اتصال به Broker لازم نیست.

فایل `server/` یک بک‌اند ابتدایی برای تست است، نه نصب تولیدی و نه پنل مدیریتی گرافیکی. برای شروع راه‌اندازی سرور، `docs/SERVER_SETUP_FA.md` را بخوانید. لازم است DNS، گواهی HTTPS/TLS، حساب‌ها، ACL، گواهی ریشه سیم800 و قابلیت MQTT فریمور واقعی تأیید شوند.

## ۶. محدودیت‌های شناخته‌شده

- هیچ **کامپایل Flutter، Arduino یا تست ماژول واقعی** در این محیط انجام نشده است. Workflows برای آزمون در GitHub آماده‌اند؛ نتیجه آن‌ها هنوز دریافت نشده است.
- برخی کدهای قدیمی SIM800 مسدودکننده‌اند؛ فریمور موبایلی یک بازنویسی کامل درایور SIM800 نیست.
- شرط ایمنی حرکت خودرو و فیزیک رله‌ها باید با سخت‌افزار اعتبارسنجی شوند؛ فقط GPS کافی نیست.
- نقشه زنده داخلی با نشانگر خودرو و بازخوانی وضعیت هر ۸ ثانیه اضافه شده است؛ کاشی‌های نقشه از OpenStreetMap اینترنت می‌خواهند. **تاریخچه مسیر و کش آفلاین نقشه** هنوز ساخته نشده‌اند.
- ثبت اولیه نیاز به دسترسی محلی دارد؛ وابستگی به IP پیش‌فرض `192.168.4.1` وجود دارد و پس از تغییر IP باید نسخه بعدی کشف خودکار آدرس داشته باشد.
- تغییر تنظیمات AP در NVS ثبت می‌شود ولی برای فعال‌شدن SSID/IP جدید ریست دستگاه لازم است.
- بکاپ/بازیابی امن و پنل گرافیکی ادمین از مرحله بعد است.

## ۷. ترتیب تست پیشنهادی

اول Firmware Verify → آزمون GPIO با بار آزمایشگاهی → Pair و Status از اپلیکیشن → ذخیره AP/GPS/SIM/MQTT → قطع Wi-Fi و بررسی حالت offline → راه‌اندازی Broker و API ابری → دریافت Status/Location از سرور → اجرای فرمان امن و دریافت ACK → بررسی زمان‌بندی و قطع و وصل GPRS.
